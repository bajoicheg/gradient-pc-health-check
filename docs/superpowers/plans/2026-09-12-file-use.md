# File-use investigation implementation plan

**Goal:** Deliver the remaining file-use investigation item from roadmap #26, after 0.12.0, as an explicitly started Analysis tool. Help diagnose an occupied local file without forcibly closing anything.

**Design:** One chosen ordinary local file; Windows Restart Manager query through StartSession/RegisterResources/GetList/EndSession. Display reported applications/services and their native PID/creation time, with optional executable metadata obtained from a limited-query process handle only when creation time matches. Preserve RM-reported names separately from verified live process metadata. A successful empty list is not proof that the file is unlocked or that deletion/rename will succeed. No handle enumeration driver, shutdown/restart, termination, file-content read, mutation, privilege change or automatic repair.

**Alternatives:** Bundling Handle/Process Explorer creates a dependency and separate licensing/distribution concerns. Undocumented system-handle enumeration adds access, timeout and compatibility risk. The documented Restart Manager interface is a bounded first implementation, not feature parity with either tool. RM manages temporary OS session/registration state; 'read-only' describes the selected file and applications, not a claim of zero OS registry writes.

**Architecture:** New FileUseModels.cs, FileUseCore.cs (path, identity, display rules), FileUseService.cs (injectable session lifecycle), FileUseWindowsSource.cs (four RM APIs and query-only process metadata), FileUseReport.cs and FileUseForm.cs. Add only self-test/menu wiring to Program.cs and version/docs updates. Current health model, context/Temp/UAC/portable semantics stay unchanged. No new packages or workflow permissions.

## Acceptance
- Select or paste a full local drive path, including spaces/Unicode; quoted paths accepted. Reject relative paths, URLs, wildcards, ADS, device/UNC paths and directories explicitly. Do not expand environment variables or traverse reparse points; exclude mapped network drives. Native access errors are not 'no users'.
- Four bounded GetList attempts; maximum 1024 results. ERROR_MORE_DATA triggers a bounded capacity retry. Partial native arrays on error are not treated as valid records. Session cleanup is attempted exactly once on every exit after successful start, including cancellation/error. Cleanup failure is recorded without hiding the obtained list.
- Cancellation is cooperative between native calls; a running native API may delay return. One in-process collector gate prevents reopening windows from accumulating RM sessions. No promise of a hard native deadline.
- Read metadata through PROCESS_QUERY_LIMITED_INFORMATION, GetProcessTimes and QueryFullProcessImageName on the same handle. Only exact RM PID/FILETIME agreement permits live path/name association; PID reuse, exit, denied access and invalid timestamps remain visible. RM friendly names remain sourced to RM.
- UI idle on open; explicit choose/repeat/stop, progress/elapsed, literal search/numeric sorting/details, previous/current attempts, clipboard and unique full-snapshot HTML/JSON. Search is not redaction. Any previous attempt retains its own target/account/time. No misleading cross-file comparison or unlock verdict.
- Advice: save work, verify the reported application, close it normally when appropriate, repeat the real failed operation. Do not recommend restarting critical services merely from native flags.

## Validation and sources
Native integration creates a dedicated temporary file, keeps its handle open, requests RM users, verifies the current process identity, closes only its own fixture handle, retries and checks unchanged file bytes. No real user file, network target or repair is used. Native Windows Server CI is distinct from Windows 11/UAC/RDP/protected-process/cloud-file/DPI acceptance.
