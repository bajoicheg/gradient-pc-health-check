# Типовые проблемы рабочих ПК: каталог и границы автоматизации

Дата исследования: 2026-09-11. Платформа: Windows 11 x64. Планируемая версия первого расширения: 0.5.0.

Это приоритеты развития продукта, а не измеренный рейтинг частоты: выгрузка заявок Service Desk не анализировалась. Документы Microsoft подтверждают диагностические механизмы и способы устранения, но не проценты обращений.

## Приоритетный каталог

| Приоритет | Симптом | Проверка | Устранение и границы | Состояние |
|---|---|---|---|---|
| 1 | ПК медленно работает | CPU/RAM, TOP процессов, устойчивые замеры | Разобрать источник нагрузки; не завершать процессы автоматически | Базовая диагностика уже есть |
| 2 | Мало места на диске | Свободные GB и проценты системного диска | Подтверждаемая очистка старых обычных файлов Temp пользователя; не трогать Prefetch/профили/системные каталоги | Автодействие уже есть |
| 3 | Сеть не работает | Активные NIC, пригодные IPv4/IPv6, link-local/APIPA | Проверить подключение/DHCP/VPN; не выполнять reset или DHCP release | Первое расширение |
| 4 | Не открывается ресурс по имени | Наличие DNS на интерфейсе с пригодным IP; это ещё не проверка разрешения конкретного имени | Локальная очистка DNS-кэша только отдельным подтверждением по симптому; не менять DNS/proxy | Проверка конфигурации в первом расширении; активная проверка конкретного FQDN в следующем |
| 5 | Не печатает | Установленные принтеры, default, WorkOffline, driver-reported status, Spooler | Открыть параметры печати, проверить выбранный принтер и очередь. Перезапуск службы только вручную и по согласованию; не удалять задания | Первое расширение |
| 6 | Долгий запуск | Uptime, автозагрузка, активные процессы | Согласовать отключение необязательного ПО; не выключать защиту/VPN | Базовая эвристика уже есть; длительность загрузки требует отдельной телеметрии |
| 7 | Сбои/ожидание Windows Update | Pending reboot, история ошибок; остановленная служба сама по себе не неисправность | Сохранить работу и согласовать перезагрузку; действовать через корпоративный канал обновлений | Pending reboot уже есть; разбор истории и кодов — следующий этап |
| 8 | Приложение падает или зависает | Event Log по Provider/Event ID и повторяемости | Сохранить данные, выяснить затронутое приложение, использовать Repair; не сбрасывать профиль автоматически | Общие события уже есть; диагностика конкретного приложения — следующий этап |
| 9 | Драйвер/устройство не работает | Win32_PnPEntity: Present и ConfigManagerErrorCode | Показать код и маршрут проверки; драйвер только из доверенного корпоративного/OEM-источника; не включать отключённые устройства | Первое расширение |
| 10 | Диск зависает/ошибки накопителя | Совместные busy+queue, доступный HealthStatus | Проверить резервную копию и эскалировать; не заменять проверку накопителя очисткой Temp | Базовая диагностика уже есть |
| 11 | Повреждение компонентов Windows | Симптомы и журнал; наличие ошибки не доказывает повреждение | Осознанные DISM затем SFC через существующий UAC-worker, повторная проверка | Автодействия уже есть, не выбираются по умолчанию |
| 12 | Защита/доступ/учётная запись | Видимость security products; отдельные будущие проверки времени и авторизации | Эскалация ответственному; не отключать EDR, GPO, MFA и не чистить учётные данные | Видимость продукта уже есть; достоверная оценка защиты/авторизации — следующий этап |

## Первое расширение: интерфейс и контракт

Новая команда «Типовые проблемы» в меню приложения открывает отдельное окно проверки сети, печати и устройств. Это дополнительные проверки; их результаты не подмешиваются скрыто в прежний Health Score/Coverage. В окне видны статус, факты и шаги инженера. Снимки можно повторить, скопировать и сохранить локально в HTML/JSON. Предыдущий и текущий снимки не являются доказательством причинно-следственной связи.

Статусы: WARN — есть требующее внимания наблюдение; INFO — ограниченная/контекстная информация, не доказательство исправности; UNKNOWN — данных недостаточно; OK — в успешно выполненной конкретной проверке кодов ошибок не найдено. Нет активных NIC не доказывает отказ интернета, наличие IP/DNS не доказывает достижимость, неизвестный статус принтера не означает готовность.

Read-only сбор не делает собственных ping/HTTP/DNS-запросов внешним узлам. WMI/службы Windows могут обращаться к своим поставщикам данных; полная сетевая изоляция приложения этим не гарантируется. Не собираются содержимое документов печати, пароли, cookies и история браузера. Имена устройств и IP-адреса в экспорте могут быть чувствительными: такие отчёты нельзя без проверки размещать в публичном репозитории.

Разделы Windows открываются только из фиксированного списка URI. Это навигация, не автоматическое исправление. Единственное дополнительное UI-обращение к автоматическому действию использует уже существующий `FlushDns`, после отдельного предупреждения; worker/allow-list не расширяется. Для неправильной IP-конфигурации или отсутствующего DNS эта кнопка не предлагается.

## План проверки

1. RED: синтетические сценарии против пустого контракта оценивания; сборка должна пройти, проверки поведения — завершиться ошибками.
2. GREEN: реализовать чистый оценщик, локальные сборщики и окно; прогнать новые и прежние self-tests, warnings-as-errors и negative worker tests.
3. Проверить HTML encoding, безопасный список Settings URI, переходы busy/cancel/close, отсутствие изменений worker и зависимостей.
4. Пилот Windows 11: IPv4/IPv6, VPN и несколько NIC; действующий и выключенный принтер; GPO с отключённым Spooler; PnP 22/28/43; отказ WMI; закрытие во время сбора; проверка симптома после действий. CI на Windows Server не заменяет этот пилот.
