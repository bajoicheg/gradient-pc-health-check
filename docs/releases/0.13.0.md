# 0.13.0 — Who is using this file?

## Use

Open **Анализ → Кто использует файл…**, choose one ordinary local file or paste its full path, and press **Проверить / повторить**. The window opens idle. It shows application/service names reported by Windows Restart Manager, native PID and creation time, application type and the session number where meaningful. Search matches literal application/service/PID/executable text; PID and session columns sort numerically. Select a row for full metadata and guidance.

Additional executable metadata is queried with the current token and is displayed only if PID and exact creation FILETIME agree with the Restart Manager record. An exited, protected or reused PID cannot inherit the name/path of another process. RM friendly application names are kept separately from verified executable names. Multiple services in one process retain their separate rows. A record with invalid creation time does not suppress metadata for a subsequent valid same-PID record.

Save work and verify the reported application before closing it normally. Retry the original rename/delete/open operation separately. The program does not close applications or handles belonging to them, terminate processes, restart services, delete/change the file, read its contents or elevate privileges for this investigation.

## What the result means

A successful empty result says **Restart Manager did not report applications using the registered file**. It does not prove the absence of all locks, sufficient filesystem permissions or that a rename/delete will succeed. A failed/cancelled query is distinct from an empty successful query. RM's application-status/restartable/reboot-reason flags are preserved as source evidence, not advice to restart a critical process or the computer.

The selected file and processes may change while collection runs. The path is not an immutable file identifier, and the path metadata check is not a filesystem lock or race-proof authorization boundary. This is a documented API-based first investigation, not full Process Explorer/Handle functionality or kernel-handle enumeration.

## Path and privilege scope

One full local drive path is supported, including Unicode, spaces and quoted Explorer paths. Relative paths, URLs, UNC/mapped network drives, device prefixes, masks and alternate data streams are not supported. Encountered reparse points and directories are rejected. Reserved DOS components such as NUL.txt, COM1 or LPT² are rejected before native queries; normal lookalikes such as COM10.txt remain accepted. These rules concern the selected data-file path only: the utility itself still supports any executable folder/name. Long-path/provider restrictions imposed by Windows are reported as errors, not bypassed.

The tool runs under its existing normal/elevated account. It never silently switches to the desktop user's credentials. The captured process/session/context and path are stored per attempt. Separate administrative execution may expose more data but does not guarantee access to every process or file. No worker, UAC, CleanTemp or elevated-preview policy was changed.

## Cancellation, limits and reports

The query uses at most four RmGetList calls and 1024 records. ERROR_MORE_DATA causes a bounded capacity retry; records from failed calls are not used. A successful count larger than the supplied capacity is rejected by both native adapter and service contract. ERROR_CANCELLED 1223 remains in the saved error-code field. Identity queries are reused for the same valid PID within an attempt without merging native service records.

One form-level collector gate prevents concurrent/reopened windows from accumulating native work. Cancellation is cooperative between calls, not a hard native timeout. Closing a collecting window requests cancellation. Every successful StartSession is followed by exactly one attempted EndSession, including registration/list/identity exceptions and cancellation; cleanup failures are reported without discarding a completed list. RM itself owns temporary OS session/registration state, including registry activity; query-only behavior does not mean absolutely zero OS writes.

Stopping retains any completed list in application memory. **Сохранить HTML / JSON** writes both current and previous attempts in a unique folder. Search filters are not redaction: each report contains the full retained attempts with their own target paths, accounts, timestamps, codes and warnings. A new attempt shifts the earlier result to the previous slot, so export needed evidence before further repeats or closing. Changing the input path does not relabel existing results as belonging to the new path. Clipboard provides a scoped summary. Reports may contain sensitive paths, application/service names, executable paths and account/SID context.
