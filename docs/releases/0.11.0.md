# 0.11.0 — Execution context, action availability and elevated Temp preview

## User-visible changes

The main window now distinguishes the account running the process from the user belonging to its Windows session. Its context strip identifies a standard user, an administrator with a filtered token, an elevated administrator, a full administrator token without a UAC-linked pair, or incomplete evidence. These are detected facts, not manually selected permission modes.

Open **Права и доступные действия…** for token/session/profile details and a seven-operation availability matrix. The action table shows **Доступно сейчас**, **Требуется UAC**, **Недоступно** or **Вручную** before confirmation. Unavailable operations cannot remain selected. The context is captured again before applying; a newly unavailable selected operation stops the requested batch rather than silently applying only a subset. Windows can still deny a command or UAC request.

**Read-only user Temp preview is allowed with an elevated process.** The target is the identified user of the process's own Windows session, including a separate technician account launched into that session. The preview, overview and exports identify the actor, target account/SID, exact path and deletion availability. A read failure remains unavailable evidence; it does not become an empty successful scan. The preview never deletes files or requests elevation itself.

Deletion remains a different operation: **CleanTemp requires a non-elevated process with matching process/session user SIDs and matching verified profiles**. An elevated technician can inspect the user's Temp but must run as that user without elevation to request this existing cleanup. This does not alter UAC, impersonate the user, load a profile or modify access permissions.

## Scope and context rules

- Session identity uses WTS with the current process SessionId, not the physical console's Win32_ComputerSystem.UserName. Session 0 and unknown session users do not receive guessed profiles.
- For a matching SID, the process token supplies its profile directory. Otherwise the session user's SID selects its ProfileList record. Only SystemDrive/SystemRoot machine variables are expanded; another account's USERPROFILE/USERNAME is never substituted.
- Temp remains the existing **profile\\AppData\\Local\\Temp** scope. This release does not discover arbitrary application-specific TMP paths or all LocalAppData redirection configurations.
- Startup review still reads **HKCU and personal Startup of the process account**. The context view explicitly distinguishes this from session-user Temp. It does not silently impersonate the desktop user or change which hive is read.
- A token's Administrators SID describes its logon token, not a fresh membership query to AD. Effective rights and elevation are separate nullable facts.
- Context discovery uses query APIs; WindowsPrincipal may duplicate a primary token at identification level for its membership check. No duplicated token is applied to the caller and no privileges are enabled. Native name/SID lookup and Windows providers may cause OS network activity.

## Remediation and audit

| Action | Normal same-user process | Elevated process |
|---|---|---|
| Temp preview | Allowed when the session profile is known | Allowed when the session profile is known |
| CleanTemp | Allowed with verified matching identities/profiles | Unavailable; restart normally as the session user |
| FlushDns | Current token, no automatic UAC retry | Current token |
| DISM / SFC | Separate UAC worker | Existing administrative token, no redundant UAC |

Machine repairs no longer depend on finding a user profile. Every actual action re-captures its executor context, uses the hardcoded action policy and stores account/SID, session, effective rights, elevation, timestamp and target scope with the action result. Saved UI context is not an authorization credential. Mixed batches preserve the admin worker's facts for DISM/SFC and the normal parent's facts for CleanTemp. The legacy batch Elevated field is aggregate only; use per-action context for attribution. Old records with no context remain unknown.

The original GUI still collects the after-snapshot in its original token. Elevating the repair worker does **not** silently elevate later diagnostics. Main HTML/JSON, clipboard and the before/after view now retain the relevant identities. Other tool snapshots retain their existing collection contracts; this release does not claim that every historical or auxiliary report has been re-collected with the new schema.

Same fixed commands, selected-action confirmation, pipe/session/nonce validation, timeouts and portable EXE location/name remain. No new repair command, automatic account switch, profile impersonation, background service, credential storage, package, driver or workflow permission is introduced. No automatic privileged diagnostic collector is added.

## Verification

The new tests cover 30 policy/preview cases, seven native/UI/serialization cases and eight action-boundary review cases. The final exact PR/main runs, any fixes discovered by those tests, and release hashes are recorded in PR #32 after execution. Counts here describe test scope, not an assertion that an arbitrary later head passed.

The read-only preview tests use disposable synthetic profiles/files, including a synthetic elevated actor inspecting another synthetic user's profile. Native tests read the current Windows token/session; they do not generate a real UAC credential dialog. The protected-root cleanup cases verify refusal without deleting the fixture. They do not clean the runner's or any workstation user's Temp, run DISM/SFC or flush DNS.

## Required Windows 11 pilot

Run under standard user, local-admin normal launch, elevated same-account and elevated other-account UAC in the same desktop/RDP session. Check actor/session identity, exact Temp root, preview availability and correct deletion refusal. Include unknown/denied WTS, session 0, unavailable profiles, redirected profiles and nondefault Temp configurations. Check available action selection and mixed-batch per-action reports without confusing the administrator with the target user. Check the main/context windows at 100/150/200% DPI.

Hosted Windows Server tests are not this pilot. Access to a source is not guaranteed by admin status; protected processes, WMI/OEM providers and policy restrictions may still deny data. UI close/cancel and long-running native-provider behavior remain environment-dependent. Authenticode signing remains absent; build provenance is not a publisher signature.
