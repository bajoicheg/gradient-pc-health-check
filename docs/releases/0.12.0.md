# 0.12.0 — Local network endpoints and process evidence

## Use

Open **Анализ → Сетевые соединения и порты (TCP/UDP)…**. The window opens idle. **Собрать / повторить** reads four local Windows tables, not remote hosts. It shows TCP4/TCP6 connections/listeners and UDP4/UDP6 local bindings, local/remote addresses and ports where meaningful, native PID/state, and available process names.

Search literally by process, PID, IP, port or state; filter all/TCP/UDP/TCP LISTEN/TCP ESTABLISHED/changes. PID and ports sort numerically. The grid displays up to 2000 matching observations; search and HTML/JSON use the entire retained snapshots. Grey `Больше не наблюдается` rows are from the previous snapshot, not current endpoints. The details pane explains each row and process match. The overview identifies the collecting account and token/session context from 0.11.0.

**Остановить сбор** retains completed tables in memory and marks the attempt cancelled. Export is separate. Repeat moves the current attempt to the previous slot; export needed evidence before further repeats or closing. **Сохранить HTML / JSON** creates a separate folder with both complete retained snapshots, source statuses, warnings, timestamps and comparison observations. Search filters are not redaction. Copy produces a Service Desk summary. Exports can contain sensitive accounts/SIDs, processes and network addresses.

## Measurement semantics

- GetExtendedTcpTable/GetExtendedUdpTable OWNER_PID calls read available local TCP4/TCP6/UDP4/UDP6 tables independently. Each has its own outcome/time/count. An empty successful table is different from an unavailable one.
- UDP reports local socket bindings, including sockets used for sending; it does not identify remote UDP peers. LISTEN remote-address/port fields have no meaning and are shown as unavailable.
- Wildcard addresses such as 0.0.0.0 and :: are retained. LISTEN/BOUND does not prove exposure to the internet or reachability through firewalls and routing. ESTABLISHED does not prove application health, trust or throughput.
- Process identity is observed before and after table reads. Only matching PID, creation time and name decorate a row; exited/new/reused/ambiguous identities remain unconfirmed. PID 0 and terminal TCP CLOSED/TIME_WAIT/DELETE_TCB states are not assigned a current process name. The native PID is still preserved.
- There is no account-owner lookup, command-line collection or process manipulation in this window. Use the existing process-detail tool for a separate investigation; historical or disappeared rows are not automatically attributed to a current PID.

## Snapshot comparisons

Only chronologically ordered snapshots with the same nonempty host, process SID, session and known token rights are comparable. Each corresponding table must have been collected completely. Missing/partial/failed tables cannot imply newly appeared or disappeared endpoints. Duplicate endpoint tuples are preserved and marked ambiguous rather than paired arbitrarily.

Comparison keys contain table, local/remote addresses and ports, and native PID; states are compared separately. Matching stable processes with different creation times are labelled as a different process with the same PID. Labels describe what was observed in two samples: appeared, no longer observed, state changed, observed again, ambiguous or not compared. They are not exact creation/termination timestamps or proof of continuous socket identity. Connections can appear/disappear between samples unnoticed; tuple reuse is possible.

## Limits and unchanged boundaries

At most 5000 rows per native table, a 16 MiB native buffer, four buffer-size retries and 8192 process objects per identity observation. Cooperative cancellation is checked between native operations; no hard timeout or continuous background monitoring is promised. Tables/processes are not an atomic OS snapshot. Name lookup needed by existing execution-context discovery may involve OS account services, but this feature performs no reverse DNS or active network probe.

No external tool downloads, packet capture, TLS/HTTP probe, connection closing, process termination, firewall/network changes, elevation or automatic repairs. It does not alter the main health score, action allow-list, UAC/Temp boundaries, portable folder/name policy, dependencies or CI permissions. Windows access restrictions remain visible rather than prompting for elevation.

## Validation

Test-first Windows run 34701167227 on `16285706e237290b55c75a512ea0676a77fd8287` compiled with zero compiler warnings/errors and passed the previous suites, then reported 0/39 endpoint cases on explicit stubs (exit 243). Expanded contract run 34701311921 on `4d8f802993d65b1a8e72f3df6d1e535e23461f0e` also compiled, passed prior suites, and reported 0/39 behavior plus 0/8 integration because the source/window/export were absent.

Behavior cases cover both address families, network byte order, scope IDs, absent remote data, unknown states, malformed buffers, truncation, missing process identity/PID reuse, snapshot comparison failures/duplicates, literal filtering, cancellation and encoded full reports. Integration cases create disposable loopback IPv4/IPv6 TCP connections/listeners and UDP bindings, inspect native owner PIDs/ports, match the test process, and verify idle UI/menu/export. These test sockets exchange no application payload and do not connect to external hosts. Final GREEN, main/release and downloaded-byte verification are recorded on PR #33; RED alone is not release readiness.

Real corporate Windows 11 standard/elevated/alternate-account/RDP sessions, IPv6 scoped/link-local traffic, VPN/network churn, table-size limits, UI 100/150/200% DPI and responsive cancellation need pilot testing. Hosted Windows Server CI is not this pilot. Authenticode signing remains absent.
