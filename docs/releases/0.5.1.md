# 0.5.1 — Consistent system-volume diagnostics

## Changes

Assessment, the main dashboard, the clipboard summary and HTML/before-after reporting use the same system-volume selector. The local Windows system directory supplies the drive identity; the EXE location and current working directory do not. Missing identity or measurements never fall back to C: or an arbitrary other volume.

Drive-root forms such as `c:`, `C:\`, `C:/` and surrounding whitespace are normalized without modifying source records. Duplicate normalized identities and out-of-range/nonfinite capacity/free-space values are unavailable evidence, not a confirmed health fault. Their coverage contribution is removed and the existing data warning is shown; missing data alone does not preselect cleanup. A measured zero free space remains a real critical finding.

The System tab and HTML System section identify the local Windows volume. Before/after comparison names that volume and retains an em dash for missing measurements and unavailable deltas.

This is a correction to local workstation diagnostics and live before/after reports, not an offline cross-machine JSON-import feature. Snapshot schemas, collectors, performance thresholds, privileged worker, IPC, elevation, remediation allow-list, dependencies and workflow permissions are unchanged. Selection validates measurements for assessment/presentation; it does not introduce a general-purpose serializer for arbitrary malformed or nonfinite JSON input.

## Test-first evidence

Test-only commit `7f59f07137d35b1bbb8aee7149a062a5b78c8231`, Windows EXE run `34632165133`, compiled with 0 warnings and 0 errors. Existing suites passed, then the new system-volume suite reported **4/24 passed** with exit 170. The failures reproduced normalization/consumer mismatches, invalid/ambiguous measurements and the absent unified selector contract.

The 24 synthetic cases cover an ordinary Windows root, normalized root forms, dashboard/HTML agreement, named comparisons, missing after-values, invalid measurements, duplicate identities, true zero free space, D: with C: as a decoy, invalid explicit roots and immutable input data. The actual final PR/main runs determine GREEN and release status; the test-only RED run does not establish release readiness.

## Pilot boundary

On managed Windows 11, check the main metric, System tab, clipboard and before/after report against the actual OS volume. Include a workstation or VM with Windows on a non-C volume and a portable EXE launched from another volume. Confirm that unavailable telemetry never reports another disk's free space and does not automatically select cleanup.

Hosted Windows Server CI does not replace this workstation pilot, real WMI/provider/GUI/UAC testing or Authenticode signing. The existing 0.5.0 common-problem window and its pilot requirements remain applicable.
