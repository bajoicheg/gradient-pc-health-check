# 0.8.0 — Incident-window events and process details

This release continues the already approved issue #26 roadmap after 0.7.0. It adds two read-only tools inside the existing portable EXE; it does not change the main Health Score/Coverage or repairs.

## События за время сбоя

Open **Анализ → События за время сбоя…**, select the interval in the Windows local time zone, then choose **Собрать / повторить**. The window opens idle. The default interval is the preceding hour; the maximum interval is seven days. Invalid or ambiguous local DST times are rejected rather than guessed. The query uses explicit UTC bounds, inclusive at both ends.

Only local **Application** and **System** are read. Each source is queried newest first, with at most 1000 records retained per log in the GUI; an extra record detects truncation. A 20-second budget is checked between provider calls for each source. The service accepts a validated 1–5000 record limit; the GUI deliberately keeps the fixed 1000-record default. Security, remote logs, subscriptions and arbitrary XPath input are not included.

The table includes timestamp, log, Event ID, level, provider, emitter PID and Record ID. Select a row to view its message and metadata. Search matches literal text in provider/message/Event ID/emitter PID; filters also select an exact channel, Event ID (`-1` means all), and Critical/Error/Warning. These filters apply to the collected subset: they do not query events that were skipped by the collection limit. Narrow the time interval and collect again to investigate older events.

Missing or out-of-range timestamps are not silently attributed to the interval. A denied log or formatting error is visible separately from the other log's data. Metadata is retained when the message cannot be formatted. Messages over 16,384 UTF-16 characters are explicitly marked truncated; truncation avoids splitting a surrogate pair. The count of saved events is not a total for unseen, cleared or overwritten history.

## Подробности процессов

Open **Анализ → Подробности процессов…**, then collect the current process snapshot. The table has typed PID, start time and working-set columns, name, parent PID, executable path and owner state. The detail pane adds raw command line, session, thread and handle counts and collection warnings. The exact WMI CreationDate key is retained in the exported snapshot and used for owner identity checks. Search covers name, path, command, PID, parent PID and session ID. Memory is working set expressed in MiB, not private committed memory or a performance trend.

Collection uses local Win32_Process, keeps at most 1024 process records in the GUI and checks a 20-second budget between provider calls. Missing protected-process fields remain unavailable; an empty path does not imply malware. Command lines are only shown as text: they are not expanded, executed or used to load a file. No process is started, terminated or modified by this tool.

Choose a row and **Проверить владельца** for a separate read-only GetOwner request. PID and exact CreationDate must match immediately before and after the request. If the process has exited, its PID has been reused or the identity is unknown, no owner is attributed to the old row. Denied, cancelled and stale checks are stored with their timestamp. Successful owner evidence is an observation at that time, not a durable process identity guarantee. The latest evidence for that row is shown; all checks in the current snapshot are retained in the export.

These are current processes, not a historical process inventory. A PID stored in an old event refers to its emitter and is not automatically mapped to a present process or to the application named inside that event's message. Temporal coincidence alone is not root-cause evidence.

## Operation, reports and privacy

Both windows provide repeat/cancel, elapsed progress, full row details, clipboard summary and local HTML/JSON export. A shared gate prevents accumulating simultaneous provider workers when a window is closed/reopened. Cancelled/partial attempts are explicitly labelled; they are not a healthy result. Changing interval fields does not reinterpret an existing snapshot's captured times.

JSON uses `SchemaVersion: 1`, the full typed Snapshot, current Filter and VisibleCount. HTML also retains the full collected snapshot and warnings; search is not a redaction/export filter. Variable text is HTML-encoded. Exports use a new timestamp/GUID directory and create-new files, never overwrite an earlier report. A partial file-write failure is reported, not called a complete export. Clipboard summaries show at most 12 matching records, 10 warnings per event source and the last 10 owner checks; full available evidence remains in the files.

Reports may contain account names, command-line secrets, paths and event messages. Review/redact before sharing outside the intended support channel. No automatic uploads, external probes, event writes, log clearing or new remediation actions are added.

Cancellation and budgets are cooperative. ReadEvent, message formatting, WMI enumeration and GetOwner can take longer inside a system/provider call. This release does not claim hard process isolation or immediate cancellation of OS-internal work. A complete read means the requested collection finished, not that the computer or application is healthy.

## Preserved behavior and remaining pilot

Any EXE location/name and UAC behavior from 0.5.2 remain unchanged, as do Temp/startup review, DNS/TCP diagnostics, existing collectors/thresholds, worker/action allow-list, dependencies and CI permissions. No other utilities' source or executables are bundled. The PE is still not Authenticode-signed.

Hosted CI used Windows Server, not managed Windows 11. Pilot: real incident data, unavailable event resources, protected and rapidly exiting processes, standard-user permissions, DST and local-zone settings, 100/150/200% DPI, close/cancel during slow provider calls and report privacy. Interactive UAC and actual DISM/SFC remain separate checks; nothing was deployed to user workstations.
