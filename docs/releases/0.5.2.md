# 0.5.2 — Portable administrative actions

## User-visible change

Removed the app's fixed directory and EXE-name requirement for administrative remediation. The current EXE is used directly for UAC, whether it is in Downloads, another directory or renamed. There is no automatic copy or installation. Close the app before moving/renaming the executable. OS access checks and enterprise execution policy remain effective.

## Implementation

The GUI-side canonical-path refusal and worker-side path gate were both removed. `Environment.ProcessPath` supplies the current launch file. A tested `ProcessStartInfo` factory preserves that absolute path, requests `runas` with `UseShellExecute=true` and uses the Windows system working directory. The filename is not interpolated into a cmd/PowerShell command.

Action confirmation, DISM/SFC token requirements, fixed commands, timeouts, pipe/session/nonce checks and standard-user-only Temp cleanup remain. The unused copy/install bootstrap is still disabled. This intentionally relaxes the prior deployment-location boundary and does not add code signing or guarantee protection against replacement in a writable directory.

Published asset filenames remain conventional; this does not restrict the downloaded application's runtime filename.
