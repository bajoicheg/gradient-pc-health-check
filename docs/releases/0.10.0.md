# 0.10.0 — Folder space analysis and detailed storage evidence

## Use

Two tools are added to the existing **Анализ** menu. Both open idle and collect only after **Проверить / повторить**. Existing tools, arbitrary EXE location/name, UAC and repair commands are unchanged.

### Место по папкам…

Select an absolute folder path and start. The result contains bottom-up logical file-size totals, folder/file counts, each folder's own values, and the largest 200 observed files. Switch between all folders, immediate subfolders and largest files; search literally across the saved snapshot. Folder tables show at most 2000 matching rows; search covers all collected rows and export is not limited by the UI filter.

Defaults bound collection to 200000 encountered entries, 20000 folders and a 120-second cooperative budget. These limits are checked between provider calls, not an instant timeout for an unresponsive filesystem. Hidden entries are included. Reparse points are skipped, initial root ancestors and traversed directories are checked, failures and incomplete branches are visible. Already processed metadata is retained on cancellation or budget exhaustion.

Only metadata is read. Nothing is deleted or opened for content. Logical byte totals are not physical allocation, available disk space, or a cleanup recommendation. Hard links count once per name; compression, sparse allocation, alternate data streams and inaccessible content are not inferred. Nested folder totals overlap and must not be summed together. Concurrent changes are possible; path checks do not provide an atomic snapshot or a secure handle-based traversal guarantee. Network/cloud paths may cause provider traffic even though the application does not read file contents.

### Подробности накопителей…

Reads local `root\Microsoft\Windows\Storage` / `MSFT_PhysicalDisk` and the documented `MSFT_PhysicalDiskToStorageReliabilityCounter` association from each original object. At most one associated row with the same nonempty DeviceId is accepted. Unavailable, mismatched, ambiguous and invalid counter values are explicit rather than converted to zeros.

Fields include friendly name, DeviceId, firmware, size, raw health/media/bus/operational codes, and available temperature, device temperature limit, wear, power-on hours and uncorrected read/write counters. Wear is consumed estimated endurance, not remaining health. Historical error counters do not establish the cause of the current incident. Temperature is compared only with a positive reported device limit, not an invented universal threshold.

The collection budget is 64 displayed disks / 30 seconds between provider calls. A stopped or failed source retains completed records. Unsupported/denied/USB/RAID/controller-specific counters remain missing; the program does not auto-elevate to obtain them. Device attention and collection completeness are separate. This is not raw SMART transport, a surface test, a benchmark, drive-letter mapping or a guarantee of health. No device method is invoked.

## Results, stop and export

Stop retains completed data in memory with a partial/stopped outcome. Cancelling while waiting to start leaves the previous snapshot, explicitly identified by its timestamp. Export to disk is a separate action. New scans replace in-memory results; export first when retention is needed. HTML/JSON always contain the entire collected snapshot, including warnings and all saved folder rows, regardless of search. The HTML includes a size-share view of the 15 largest immediate subfolders.

Exports create a unique directory and do not overwrite earlier evidence. I/O failure may leave a partial export directory and is reported, not declared successful. Paths/device identifiers may be sensitive. Search is not redaction. No report upload is added.
