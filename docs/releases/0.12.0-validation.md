## Review and limits

Direct source/diff review, not an independent human or subagent review. Existing runtime changes are limited to Program test/menu wiring and version metadata; the endpoint feature is implemented in its own files. Existing diagnostic collectors, worker/IPC, context/Temp policy, assessment thresholds, packages, workflow files and repository protection were not modified.

Native integration creates disposable loopback TCP listeners/connections and UDP bindings on IPv4/IPv6, checks actual owner PID/ports/state and stable attribution of the test process. It exchanges no application payload and contacts no external host. UI checks construct the window and verify its idle state/menu/export controls; they are not a visual DPI inspection. Source-specific failures, unknown process identity, duplicate tuples, PID reuse, truncation and cancellation are tested synthetically.

The feature reads OWNER_PID layouts from local IP Helper tables. Per-table counts/outcomes are separate from process-name completeness. Comparisons are sampling statements, not exact lifecycle events or a security verdict. No live tracing, reverse DNS, active probes, packet capture, connection closing, process termination or privileged broker is added.

Hosted runtime: Windows Server 2025, .NET SDK 8.0.425. Windows 11 normal/elevated/other-account/RDP, scoped link-local IPv6, VPN/network churn, actual access-denied environments, GUI 100/150/200% DPI and long provider calls remain pilot checks. No interactive UAC or real DISM/SFC/DNS-flush/user-Temp cleanup was run. Authenticode remains absent.
