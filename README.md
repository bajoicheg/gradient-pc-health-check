# Gradient PC Health Check

Внутреннее Windows-приложение Service Desk для первичной диагностики жалоб **«компьютер сильно тормозит»** и безопасного применения выбранных remediation.

Текущая версия разработки: **0.3.5 pilot**.

Для инженера это один GUI-файл `Gradient-PC-Health-Check.exe`. Диагностика запускается автоматически; рекомендации отображаются с галочками только там, где действие разрешено автоматизировать. По кнопке **«Применить выбранное»** приложение при необходимости запрашивает UAC, выполняет allow-list remediation и затем автоматически повторяет диагностику с отчётом **до/после**.

## Что изменено в 0.3.5 по результатам первого запуска на реальном ПК

- `CleanTemp` теперь **всегда виден** инженеру Service Desk. При недостатке места он имеет тип `Рекомендуется` и предвыбран; при нормальном запасе диска — `Дополнительно` и выключен по умолчанию.
- Кнопка **«Применить выбранное»** неактивна, пока не отмечено хотя бы одно реально автоматизируемое действие. Ручные рекомендации не включают кнопку и не изображают выполнение, которого программа сделать не может.
- При выборе действий кнопка показывает их количество: `Применить выбранное (N)`.
- Вкладки TOP CPU / RAM / I/O используют числовые значения и числовую сортировку. Суффиксы `%`, `MB`, `MB/s` — только формат отображения.
- Event ID и количество событий также сортируются как числа, время события — как дата/время.
- `START-HERE.txt` в pilot package записывается как UTF-8 с BOM и проходит round-trip проверку русских строк в CI.
- После зелёной сборки `main` отдельный workflow публикует **обычный GitHub Release** с прямыми файлами `Gradient-PC-Health-Check.exe`, `.sha256` и опциональным pilot/E2E ZIP. Для обычного использования больше не нужно заходить в Actions и распаковывать вложенные ZIP.

## Coverage: отсутствие данных больше не выглядит как «всё хорошо»

Начиная с 0.3.3 Health Check отдельно рассчитывает **полноту диагностической телеметрии (coverage)**. В coverage входят ключевые сигналы: CPU, RAM, системный диск, очередь диска, health физического накопителя, Windows/build, TOP процессов и антивирус/EDR.

Если важные источники данных недоступны, приложение:

- перечисляет отсутствующие сигналы;
- добавляет отдельный WARN категории `Данные` без искусственного штрафа к Health Score;
- не показывает общий статус `OK`, пока coverage ниже высокого уровня;
- сохраняет `CoveragePercent`, `CoverageStatus` и `MissingSignals` в JSON-отчёте.

Это принципиально отделяет **«проблем не обнаружено»** от **«проблемы могли не обнаружиться, потому что часть телеметрии не собрана»**.

## Windows Event Log без штрафа за один raw count

С 0.3.3 абсолютное число `Critical/Error` само по себе больше не считается достаточным основанием для WARN/CRIT. Для диагностически значимого сигнала требуется повторяемость одного `Provider/Event ID`.

Такой подход уменьшает ложные срабатывания на рабочей станции, где за сутки может накопиться много разнородных и не связанных с жалобой ошибок. В Service Desk вывод поднимается именно тогда, когда есть устойчиво повторяющийся паттерн, который уже имеет смысл связывать с симптомом пользователя.

## Более устойчивое измерение производительности

Начиная с 0.3.2 CPU и дисковая очередь оцениваются не по одному мгновенному WMI-кадру. Программа делает **5 замеров** с короткими интервалами и использует медиану. Это уменьшает вероятность ложного WARN/CRIT из-за случайного пика в момент старта приложения или фонового короткого задания. TOP процессов по CPU/RAM/I/O снимается отдельным интервальным замером.

## UAC и доверенная точка запуска

Начиная с 0.3.4 диагностику можно запускать из Downloads или другого рабочего каталога **без административных прав**. Однако действия, требующие elevation (`CleanTemp`, `DISM`, `SFC`), разрешены только если сам EXE уже находится по каноническому пути:

`%ProgramFiles%\Gradient\PCHealthCheck\Gradient-PC-Health-Check.exe`

Автоматический bootstrap из Downloads в Program Files отключён. Без Authenticode или заранее установленного доверенного broker-а нельзя надёжно исключить pre-UAC подмену файла в user-writable каталоге. Поэтому перед пилотным применением административных remediation EXE должен быть размещён в Program Files средствами корпоративного software deployment либо контролируемо установлен инженером после проверки SHA-256.

При UAC допускается ввод **отдельной admin-учётки Service Desk**: ACL локального pipe разрешает подключение локальной группе Administrators, а одноразовые session ID + nonce связывают ответ с конкретным запросом GUI.

Worker дополнительно fail closed:

- не запускается из произвольного пути, включая другие каталоги внутри Program Files;
- не доверяет reparse-point/junction на каноническом пути;
- отклоняет mixed action list, если в нём есть хотя бы одно неизвестное действие;
- legacy `--bootstrap-worker` возвращает отказ и ничего не устанавливает.

## Разрешённые автоматические действия

- безопасная очистка старых Temp;
- Flush DNS — только по решению инженера;
- DISM RestoreHealth — только по решению инженера;
- SFC /scannow — только по решению инженера.

Prefetch, универсальный Winsock reset, очистка Windows Update, принудительная перезагрузка, завершение процессов и отключение автозагрузки не выполняются автоматически.

## Сборка, Releases и контроль

Windows 11 x64, .NET 8 WinForms, self-contained single-file EXE. GitHub Actions обязан пройти E2E PowerShell harness smoke, restore, NuGet vulnerability audit, build с warnings-as-errors, source self-test, single-file publish, self-test уже опубликованного EXE, проверку worker security boundary, состава артефакта, FileVersion и SHA-256.

После успешного `Windows EXE` на push в `main` workflow `Publish GitHub Release` создаёт неизменяемый по версии tag `vX.Y.Z` и прикладывает **прямой EXE** и checksum. Если такой release уже существует, workflow не заменяет его assets автоматически.

Self-test 0.3.5 дополнительно подтверждает, что `CleanTemp`:

- при дефиците системного диска является рекомендованным и preselected;
- на здоровом диске остаётся видимым как дополнительное действие, но не выбирается автоматически.

Брендинг продукта строится вокруг общего символа ИБ Градиент — щита с буквой **G**; иконка PC Health Check должна отличаться от G-switcher зелёной цветовой схемой.
